### 1. 散文剔除（双重判据）
- **判据一 · 题名黑名单（精确匹配）**：归一化题名（去括号注释与"节选"字样）后与 55 项黑名单全等比对。覆盖主理人点名的过秦论、阿房宫赋、六国论、赤壁赋、陈情表、师说、捕蛇者说、兰亭集序、桃花源记，以及体检补充命中的洛神赋、秋声赋、进学解、原毁、祭十二郎文、柳宗元永州八记全部篇目等。
- **判据二 · 启发式（兜底防漏）**，四项数值判据同时满足才判散文：
  | 指标 | 含义 | 散文特征 | 反例参照 |
  |---|---|---|---|
  | r57 | 5/7 言句占比 | < 0.5 | 静夜思 = 1.0 |
  | avg | 平均句长 | ≥ 4.2 | 四言诗恒为 4.0 |
  | pDen | "之乎者也矣焉哉"密度 | ≥ 0.015 | 近体词 < 0.02 |
  | r4 | 4 言句占比 | < 0.7 | 鹿鸣 0.88 / 击壤歌 0.80 |

  **防止误杀的实证**：诗经四言（鹿鸣/氓/采薇/关雎）与上古歌谣（击壤歌）被 r4≥0.7 客观排除；辛弃疾《贺新郎》（词，r57=0.25 误触发前两项）列入人工复核保护名单 `HEURISTIC_PROTECT`；楚辞（离骚等）r57≈0.54 天然不触发。四言诗与楚辞全部保留在诗歌登记表中，只是其句子不是 5/7 言、不进句库，符合"是诗不要误杀"的要求。
- 剔除清单全文见 `tools/build/removed-prose.json`（含每条的 origId/题名/作者/四项统计值/剔除原因，供人工复核）。

### 2. id 重建（确定性、可复现）
- 旧库 975 条仅 747 个唯一 id（tang_401 一号 68 用等）→ 全部废弃重建。
- 新 id：`{dynastySlug}_{seq3}_{hash6}`，如 `beichao_001_e4ct7p`（敕勒歌）。
  - seq3 = 朝代 slug 内序号（按 [朝代, 归一化题名, 作者, 原索引] 码点序排序后编号）；
  - hash6 = FNV-1a 变体对 `title|author` 的 6 位 36 进制摘要，无时间因素。
- 两次构建产物 md5 一致已验证。

### 3. 同正文多题名合并
- 依正文 norm_key（去标点空白）分组：57 组 / 125 条（如己亥杂诗同一首 5 条、定风波 2 条、惠崇春江晚景/春江晚景等）。
- 选主规则：归一化题名最短者 → 作者码点序 → 构建序，确定性唯一。其余题名全部记入 `altTitles`（落盘于 poems.js 第 4 段）。

### 4. 切句与 norm_key（一句 = 单句）
- 按连续汉字段切分：逗号、顿号、句号、问叹号、分号、冒号、引号、括号、空白、全半角符号一律为分隔 → **每句一个 norm_key，整联不作最小单位**。
- norm_key = 该句去尽非汉字后的纯汉字串（如「白日依山尽」与「白日、依山　尽！」同 key）。
- 全库 norm_key 去重（143 句跨诗重句保留首现，按确定性排序），仅保留 5/7 言句进句库。

## 二、判定引擎 `src/judge.js`

纯函数、零依赖、CommonJS，小游戏原生栈直接可用：
`judge(candidate, keyword, usedKeys, pool) → { pass, reason, lineId? }`

判定顺序与 reason 枚举：
1. `FORMAT_ERROR` —— 非字符串 / 归一后为空 / 非 5、7 言
2. `INVALID_KEYWORD` —— 关键字非字池单字（「笛」已出池即拒）
3. `NOT_IN_CORPUS` —— norm_key 全等命中失败（杜撰句、库外真句均拒）
4. `NO_KEYWORD` —— 不含本轮关键字
5. `DUPLICATE` —— 已在 usedKeys（v1.4：REPEAT_LIMIT=1，usedKeys 全局去重，蕴含每人限一次）
6. `OK` —— 通过，返回 lineId 供对局记账

**norm_key 全等匹配，无任何模糊逻辑**——「今年元夜时 / 去年元夜时」这类一字之差的真实近句互不干扰、各占一席。

## 六、已验证 / 未验证边界

**已验证**
- 975 → 857 首诗、5,564 句的全量清洗结果与索引一致性（独立重算比对，非自述）。
- 散文剔除 50 条的人工可读清单；四言诗/楚辞/词（鹿鸣、氓、短歌行、离骚、贺新郎等）零误杀。
- 近似句、全半角/标点差异、重复句等判定行为与 v1.4 规则一致。

**未验证 / 交下游**
1. **source 仅到「题名·作者·朝代」**：源数据无卷次信息，未做诗文卷次补全；如需精确到卷（如《唐诗三百首·卷一》），需引入外部书目数据，本期未做。
2. **「绿水青山枉自多」等库外真实句未放行**：判定口径为"库内全等"，即玩家出真实诗句但不在库内会被拒——这是 v0.1 单机版的既定取舍；扩库或接入云函数校验属后续迭代。
3. **剔除清单未经人工复核签收**：50 条已落盘 `removed-prose.json`，建议主理人或内容同学抽检一遍（尤其 heuristic-prose 命中项现仅剩 0 条，49 条全部为黑名单命中，风险低）。
4. **生僻字**：句库含少量 CJK 扩展 A 区字（如「㧐」，曹植《名都篇》），真机字体渲染未验证，建议游戏壳侧对生僻句 UI 做兜底字体或视觉验收时关注。
5. **多音字/异体字**：norm_key 只做字符级归一，未做异体字合并（如「峰/峯」）；语料为通行简体录入，实际未发现影响判定的异体对，但未做系统性扫描。
