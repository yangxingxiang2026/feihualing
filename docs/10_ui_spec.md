# 飞花令 v0.1 · UI 设计规范（Canvas 2D 程序化绘制版）

> 设计：设小美（ui-designer-2） · 版本 v0.1 · 依据 `飞花令小游戏方案_v1.4.md` §2 玩法 / §5 视觉与适老化
> 角色资产：`canvas2d_tiger/tiger_renderer.js`（原生坐标 400×560，四状态 idle/clap/facepalm/cheer）
> 交付对象：miniprogram-engineer（寇豆码）
> **硬前提：零图片资产、零 WebGL、零九宫格贴图。** 本文所有元素均可用 `roundRect / arc / fillText / 线性渐变` 画出，凡不能的，本文直接给替代画法。

---

## 0. 结论速览（先看这 6 条，细节在后文）

1. **设计基准 375×667 逻辑像素（pt）**，Canvas 尺寸 = `screenW × dpr`，`ctx.scale(dpr,dpr)` 后全部按逻辑 px 绘制；x/w 乘 `k = screenW/375`，纵向用「顶部锚定 + 底部锚定 + 中部弹性」三段式适配 812/844 等长屏。
2. **字号地板**：正文与候选句 ≥32px，关键字大字 120px，倒计时数字 48px，首页标题 64px，结算结果字 96px。**热区地板 88×88**，全文档每个可点元素都标了热区矩形。
3. **字块拼句 = 8 块（5 正 + 3 干扰）4 列 × 2 行**，不是 12 块。原因：88px 热区 × 3 行 + 组句预览 + 按钮行在 667 高度里放不下（差 84px）。扩到 12 块的方案见 §9.3，需接受热区缩到 72 的代价。
4. **小虎诗童两种用法**：首页/结算用**全身立绘**；对局页用**半身像裁切窗口**（裁 native `(40,44,320,346)`，scale 0.3125 → 100×108）。裁切是 §7.2 给的 translate+clip 公式，不用改渲染器。
5. **决策期零干扰动效**：玩家思考时唯一允许的动效是小虎呼吸与低频眨眼（渲染器自带），**倒计时数字整数秒递变、不闪不抖**；进度环若做，只允许 1Hz 台阶式步进。
6. **关键字 120px 大字 v0.1 用 `fillText` 兜底，v0.2 必须换 20 字闭集矢量路径**（v1.4 §5.4 字体授权风险）。这是本文唯一的已知技术债，已标红。

### 1.7 适老化 6 组合矩阵（3 字号 × 亮/暗/跟随系统）

Canvas 文本不跟随系统字号，必须自建倍率。规则：

- 倍率 `S ∈ {1.0, 1.25, 1.5}` **只作用于 §1.3 表里标注可缩放的 token**；结构尺寸（关键字卡、印章、网格 cell、热区）不缩放。
- 容器高度自算：`h = max(hMin, ceil(fontSize * lineHeight) + 2*padding)`，`hMin` 见各屏表。
- 当累计增高超出可用高度，按此优先级让位：① 上句条折为单行（28→24 行高）② 组句预览条与提交按钮同行合并 ③ 网格由 2 行降为 1 行（**不允许**缩小热区，改横向分页 `换一批`）。
- 主题三态：`theme = 'light' | 'dark' | 'auto'`，`auto` 监听 `wx.onThemeChange`。**切换时不重建布局**，只重跑取色（token 换一套值）。

## 2. 全局骨架与适配

### 2.1 坐标与缩放

```
W_ref = 375, H_ref = 667
k = screenW / 375
逻辑绘制坐标： x' = x * k， 纵向 y 见 §2.2
ctx.scale(dpr, dpr)  // dpr = pixelRatio
```

### 2.2 三段式纵向锚定（适配 667 / 812 / 844）

| 段 | 锚定方式 | 公式 |
|---|---|---|
| 顶部区 | 顶锚 | `y_top = safeTop + 8`（safeTop = 状态栏高度，iOS 20，安卓 24–32） |
| 底部区 | 底锚 | `y_bottom = H - safeBottom - 12 - h_bottom`（safeBottom = 34 iPhone X 系，0 其他） |
| 中部区 | 弹性 | 在顶部段与底部段之间**居中均分**，多余高度优先给「小虎立绘 scale」和区块间距，**永不给网格/热区** |

### 2.3 右上角可点区禁令

小游戏右上角有平台「···」胶囊菜单。**禁止在该区域放任何可点元素**：
```
禁放矩形 = (screenW - 96, 0, 96, 44)   // 逻辑 px，含 statusBar 区
```
API：`wx.getMenuButtonBoundingClientRect()` 若可用则实测替换；不可用按上面兜底。

### 2.4 触摸命中

统一维护 `hotRects: [{id,x,y,w,h,r?}]`，`wx.onTouchStart/onTouchEnd` 里按**逻辑坐标**（touch 坐标已是逻辑 px，不要再除 dpr）命中。命中用「矩形优先 + 圆角忽略」，允许列表顺序遮挡（后加的在上面）。
按下态：整体 `scale 0.97`（以中心缩放）+ 填充色叠 `rgba(0,0,0,0.06)`，120ms。

```js
// 可视高度 ≈ (520-53)*s ≈ 159px，可视宽度 ≈ 320*s ≈ 109px
```

| 位置 | scale | y0 | 可视盒 | 备注 |
|---|---|---|---|---|
| 首页 idle | 0.34（长屏可弹性放大到 0.44） | 214 | 109×159 | `scale = clamp(0.30, slotH/560, 0.44)` |
| 结算 cheer/facepalm/idle | 0.40 | 196 | 128×187 | 槽高 224，底部留 29 给花瓣 |

### 7.2 对局页：半身像裁切（**关键技巧，不要改渲染器**）

对局页只有 100×108 的位置，全身像的头部只有 60px，表情（弯月眼 / 半闭眼 / 捂脸爪）读不清。用 `clip` 取头部特写：

```js
const WIN = { x: 40, y: 44, w: 320, h: 346 };   // 原生裁切窗（头 + 前爪 + 衣领）
const win = { x: 150, y: 100, w: 100, h: 108 }; // 屏幕目标盒
const s = win.w / WIN.w;                        // 0.3125
ctx.save();
rrect(ctx, win.x, win.y, win.w, win.h, 14);
ctx.clip();                                     // 圆角裁切，顶边与卡片语言一致
Tiger.draw(ctx, {
  state: st, t: elapsed, theme: 'guofeng',
  x: win.x - WIN.x * s,                         // = 150 - 12.5 = 137.5
  y: win.y - WIN.y * s,                         // = 100 - 13.75 = 86.25
  scale: s
});
ctx.restore();
```

- 裁切窗特意包含 y=296–372 的前爪区，否则 `clap`（拍手）和 `facepalm`（捂脸）动作会被裁掉。
- 裁切后小虎 = **1 个业务节点**，但内部约 180 次 path 调用 → 单帧预算见 §9.4。
- 决策期 `state='idle'`，呼吸/眨眼由渲染器自带（唯一允许的动效）。

### 7.3 状态 → 游戏时刻映射（与 `README_接入说明.md` 一致，此处只补 UI 侧）

| 游戏时刻 | state | 额外 UI 配合 |
|---|---|---|
| 首页待机 | idle | 无 |
| 出字亮相 | idle | 关键字节拍感已足够，**不给小虎加动作** |
| 玩家决策期 | idle | 禁所有 UI 动效（除倒计时整数跳） |
| 判定通过 | clap（combo≥3 → cheer） | 浮字 +1、连胜 dots 实心 |
| 判定失败 / 超时 | facepalm | 错因 pill |
| AI 接不上 / 结算胜 | cheer | 花瓣粒子（减弱动效则跳过） |
| 结算负 | facepalm | — |

### 7.4 「减弱动效」开关的实现取巧

渲染器动效全由 `t` 驱动。**减弱动效开时传冻结时间**即可，不改渲染器代码：
```js
const tDraw = reduceMotion ? 0.5 : elapsed;   // 冻结 → 呼吸/眨眼/花瓣静止
```
状态切换仍生效（换 `state` 参数即可），只是失去连续动画。

## 9. 给工程师（寇豆码）的实现注意事项

### 9.1 必须先立的三条地基

1. **`rrect()` 自己写，别用 `ctx.roundRect`**。小游戏基础库对 `roundRect` 支持不一致（低版本无此方法，直接抛错）。用 `arcTo` 四段：
```js
function rrect(ctx, x, y, w, h, r) {
  r = Math.min(r, w / 2, h / 2);
  ctx.beginPath();
  ctx.moveTo(x + r, y);
  ctx.lineTo(x + w - r, y); ctx.arcTo(x + w, y, x + w, y + r, r);
  ctx.lineTo(x + w, y + h - r); ctx.arcTo(x + w, y + h, x + w - r, y + h, r);
  ctx.lineTo(x + r, y + h); ctx.arcTo(x, y + h, x, y + h - r, r);
  ctx.lineTo(x, y + r); ctx.arcTo(x, y, x + r, y, r);
  ctx.closePath();
}
```
2. **`ctx.ellipse` 有兼容风险**（`README_接入说明.md` §6 已列待验证）。所有椭圆走 `save / translate / scale(1, ry/rx) / arc / restore` 兜底，或运行时探测一次 `typeof ctx.ellipse === 'function'` 决定分支。
3. **坐标全部逻辑 px**：`canvas.width = screenW * dpr; ctx.scale(dpr, dpr);`，之后所有几何按 §3/§4/§5 的数值写，不要再乘 dpr。`wx.onTouchStart` 的 `x/y` 也是逻辑 px，直接和 hotRects 比。

### 9.2 静态层离屏缓存（性能第一优先级）

UI 是重文字、轻动画的形态。**每帧重绘全部 UI = 白烧 GPU**。三层结构：

| 层 | 内容 | 重绘时机 |
|---|---|---|
| L0 静态层 | 背景、卡片、描边、所有固定文字、网格块 | 仅布局变更 / 主题切换 / 字号切换 / 屏切换时重绘到 `wx.createOffscreenCanvas({type:'2d', width, height})`，之后每帧一次 `drawImage` |
| L1 角色层 | 小虎（对局页裁切） | 每帧（约 1–2ms） |
| L2 动态层 | 倒计时数字、按下态、浮字、错因 pill、dots | 每帧，但只画变化中的元素 |

- 渐变对象（`createLinearGradient`）在布局阶段创建一次并缓存，**不要在 draw 循环里创建**。
- 文字截断用 `measureText`，结果按 `key = 文本 + '|' + font` 缓存进 Map，避免每帧测量。
- 关键字 20 字闭集：按 `char + size` 预渲染到离屏小画布缓存，一次一个，最多 20 个。

### 9.3 布局硬约束（不要「顺手优化」）

- **88px 热区是红线**：字块可视 72 是「内缩」，热区仍是 88×96。若产品要求 12 块，唯一合法路径是 4×3 网格 → cell 88×72（**纵向 72 < 88，需产品书面确认豁免**），且组句预览条必须与提交按钮合并成一行才能腾出 96px。我已把这个代价算清，见下表：

| 方案 | 块数 | 网格高 | 预览条 | 按钮行 | 合计（292→640 可用 348，含 4/8 间距） | 结论 |
|---|---|---|---|---|---|---|
| v0.1（本规范） | 8（4×2，cell 88×96） | 192 | 56 | 88 | 56+4+192+8+88 = **348 ✓** | **采用** |
| 扩到 12（4×3，cell 88×72） | 12 | 216 | 0（并入按钮行） | 88 | 312 ✓ | 热区纵向 72，需书面豁免 |
| 扩到 12（4×3，cell 88×96） | 12 | 288 | 56 | 88 | 440 ✗ | 超出 92px，**不可行** |

- 候选卡必须整卡可点（351×88），**不要只在文字上做热区**。
- 底部按钮行 y 用底锚公式 `yBtn = H - safeBottom - 12 - 88`，不要写死 552（667 之外的机型会压到 home indicator；812 机型上 552 会偏高 111px）。

### 9.4 中文竖排与字距（Canvas 没有 letter-spacing）

- **标题字距**：逐字 `fillText`，`x += fontSize + tracking`，`textAlign='left'` 且从「总宽 = n*fontSize + (n-1)*tracking」反推起点。首页标题：3 字 × 64 + 2 × 6 = 204（我按 180 写是因为 serif 字形左右留白，实测后以 `measureText` 校正 ±4）。
- **真竖排**（仅装饰用，如印章旁的「春」「月」点缀）：`textAlign='center'`，逐字 `y += fontSize * 1.15`，不要用 `ctx.rotate` 拼。
- **不要用空格字符凑字距**（不同机型空格宽度不同）。
- 数字（倒计时/回合）用 `textAlign='center'` + 固定盒宽，避免 1 与 8 字宽差导致整体跳动。

### 9.5 性能红线（对齐 v1.4 §4.3）

| 项 | 预算 | 本方案实情 |
|---|---|---|
| 单帧耗时 | ≤16ms | L0 缓存后 ≈ L1(2ms) + L2(<1ms) |
| 同屏业务节点 | ≤60 | 首页 12 / 对局 ~20 / 结算 ~10 ✓ |
| 绘制调用（path 级） | 未定 | 小虎单次 ~180 次 path —— **这是最大头，需真机实测**，若 >3ms 则给对局页半身像降 scale 或做帧节流（决策期 12fps 足够） |
| 内存 | ≤120MB | 离线画布 2 张 + 无位图 <20MB |
| 帧率 | ≥55fps | 决策期可降到 30fps（零动效期降帧是无损优化） |

**降级预案**（画不完时按序砍）：① 水墨底纹（H-02）② 小虎呼吸（冻结 t）③ 浮字动画（改静态 +1）④ 圆角描边细节（3px→2px）。
