**三层渲染**（spec §9）：L0 静态离屏缓存（`wx.createOffscreenCanvas({type:'2d'})`，布局/主题/字号/回合变更才重绘，每帧一次 drawImage）→ L1 小虎每帧 → L2 动态（倒计时/血条/已选字/反馈/错因 pill/按下 tint）。渐变布局期创建缓存；measureText 按 `文本|font|maxW` 缓存；rrect 全部 arcTo 手写；`ctx.ellipse` 运行时探测一次、失败走 save/translate/scale/arc/restore；禁 shadowBlur（偏移实底）。

**场景流转图**：

```
home ──点模式卡(字块拼句★推荐/点选接句)──▶ battle ──回合结束──▶ result
  ▲                                        │                      │
  └────────────设置(字号循环)·······返回‹──┘                      │
  └──────────────────────再来一局(回battle)/回首页◀──────────────┘
battle 内部相位：reveal(0.8s,不计时) → player(10s) → judge(本地1帧) → playerFeedback
  → aiThink(幽灵思考) → aiFeedback → [回合<12] reveal … ｜[=12] result
  旁路：poolEmpty(弹条换字确认) · playerTimeout(淘汰判负直接 result)
```

## 二、对局规则与判定接入（v1.4 §2.3 落地）

- 判定铁律：点选/拼句结果一律完整跑 `judge(candidate, keyword, usedKeys, POOL)`，绝不"点选即合法"；幽灵出句同样过 judge。
- **点选接句**（裁决锁 4，candidateCount 可配置）：1 正确 + 3 干扰。干扰句一律**库内同字异句**——必含关键字、非当前正确答案、互不重复；有含字历史时优先抽**已用句**作真陷阱（judge 判 DUPLICATE），其余为未用合法句（judge 放行计中）。judge 四分支由全量判定把关，错因 pill 按 reason 映射（见下）。
- **字块拼句**：8 块 4×2。5 言 → 5 正 + 3 扰；7 言 → 7 正 + 1 扰。干扰字取自**关键字邻域**（含关键字句子中的真实汉字），生成器内建 ★ 不变量：**任何含干扰块的 5/7 字排列，norm_key 都不命中句库**——拼错必判 NOT_IN_CORPUS，不允许"拼出的错句恰好是库内另一句"。CI 第 15 项做 24 组抽样全排列独立复算。
- **幽灵出句**：按关键字+难度（e/m/h/mixed 学段过滤，档内不足自动放宽）发有限手牌；回合上限 12 按接诗数判胜/和/负；玩家超时淘汰判负；幽灵手牌耗尽判玩家胜；池空弹条「此令已尽，换『X』」确认后换字并重置手牌与 usedKeys（v1.4 §2.6.6）；玩家与幽灵共用全局 usedKeys（§2.6.4）；`random([])` 不可达。
- **小虎状态映射**（spec §7）：通过 clap / combo≥3 cheer / 失败·超时 facepalm / 决策期·亮相 idle（零干扰动效：唯一动效 = 呼吸眨眼 + 倒计时整数秒 + 1Hz 台阶环）。「减弱动效」= 冻结 t=0.5，渲染器零改动。
- **错因 pill 固定映射**（ui-designer-2 定稿，逐字对齐）：NO_KEYWORD→`不含『X』字`；NOT_IN_CORPUS/INVALID_KEYWORD/FORMAT_ERROR→`非认证诗句`（三案归并）；DUPLICATE→`这句用过了`；超时→`超时了`（facepalm + 倒计时盒描边闪 1 次）；OK→不出 pill，出 `+1` 浮字。

## 4.2 真机堆帧事故修复（2026-11-18，v0.1 加固）

**现象**：真机预览黑底 + home/对局/结算三屏内容叠加糊帧（用户截图）。

**根因**：三屏全靠「L0 离屏烘焙 → drawImage 铺底」清屏，真机上 `wx.createOffscreenCanvas({type:'2d',width,height})` 存在两类已知兼容问题（部分基础库忽略对象参数尺寸回落 300×150；部分机型 2d 离屏 drawImage 失效）。铺底一旦失败，主循环又无 clearRect、单帧异常会杀死 rAF 循环 → 永久堆帧假死。

**四层加固**：
1. `platform.createOffscreen`：对象参数失败回落双参签名；创建后校验宽高不符则显式赋值兜底。
2. `draw.drawBaked`：drawImage 抛错或 L0 不可用时，直绘背景渐变兜底；三屏铺底统一走此函数。
3. `game.js` 主循环：每帧 `clearRect` 强制清屏（杜绝堆帧）；update/draw 包 try/catch，单帧异常不再杀死循环；`wx.onError`/`wx.onUnhandledRejection` 接入（真机 vConsole 可见 `[fhl]` 前缀日志）。
4. 三屏 `bake/build` 包 try/catch 降级（烘焙失败 → L0=null → 直绘模式）；home/result 动态层加空布局守卫。

**回归**：单测逐文件全过、CI 15/15、冒烟两模式全相位 ok、bundle 重打 191KB。真机验证项：铺底恢复后背景渐变应可见、三屏切换无残影；若仍异常，vConsole 查 `[fhl]` 日志定位。

## 4.5 真机黑屏（只剩小虎）事故修复（2026-11-18）

**现象**：真机预览首页纯黑背景，只有小虎可见（小虎是主画布每帧直绘，其余全在离屏烘焙层）。

**根因链**（三层，逐层加固）：
1. **离屏烘焙层内容不可见**：`wx.createOffscreenCanvas({type:'2d'})` 在部分机型/基础库上「画了但内容空」或「drawImage 不报错但输出透明」。原有兜底只补了背景渐变，**没有直绘静态内容**——所以一失败就只剩小虎。
2. **渐变创建失败退化成黑色**：离屏 ctx 的 `createLinearGradient` 异常/返回 undefined 时，`fillStyle = undefined` 被忽略，`fillRect` 用默认 fillStyle（黑）铺满烘焙层。已修：makeVGrad 全线 try/catch + 返回纯色兜底。
3. **能力自检缺失**：createOffscreen 未校验上下文能力，坏 canvas 被当成可用。

**四层修复**：
- `platform.createOffscreen`：探测 `getContext('2d')` + fillRect/createLinearGradient 能力，不足直接返回 null。
- `draw.makeVGrad`：任何异常/undefined 回落纯色 c0，永不产生 undefined fillStyle。
- `draw.drawBaked`：drawImage 成功后做**一次性像素自证**（getImageData 2,2 取 alpha；为 0 → 判离屏不可见 → 直绘背景并返回 false），WeakSet 防止重复探测。
- 三屏 `drawStatic(g)` 抽取：烘焙与直绘共用同一份静态内容代码；`!baked` 时置 L0=null 并整屏直绘（首页标题/按钮/战绩、对局页印章/上句/候选、结算页按钮均恢复）。

**回归**：新增 `tests/fallback-render.test.js`（4 条：强制离屏不可用下首页/对局/结算静态内容仍出现 + 正常烘焙路径未误伤）。全量 7 个测试文件通过、CI 15/15、冒烟 ok、bundle 197KB。

**若真机仍异常**：真机调试打开 vConsole，查 `[fhl]` 前缀日志（离屏能力/烘焙失败原因已打印）。

## 4.6 玩法难度修正（2026-11-18，用户真机反馈）

用户反馈三点：① 点选接句四个选项全都能过（无挑战）；② 字块拼句太难（目标句生僻、干扰字生僻）；③ 诗词库应优先经典。

**根因**：
1. 点选干扰项按此前派单口径生成「必含关键字的库内同字异句」——全部是 judge 会放行的合法句，等于没有干扰（4/4 可接，点谁都算对）。
2. 正确句/拼句目标/AI 手牌均从全库 5564 句均匀随机，会抽到「词人解撰河清颂」类生僻句；干扰字从关键字邻域取样，会采到生僻字。

**修正（candidates.js 重写 + ai.js 手牌偏好）**：
1. ★ 干扰项必须 judge 判不通过（生成期逐条复核）：noKw＝库内真实名句但不含关键字（NO_KEYWORD，迷惑性最高，为主力干扰）；dup＝历史已用句（DUPLICATE）；fake＝库外拼合句（NOT_IN_CORPUS，兜底）。任何意外放行的干扰直接弃用。
2. ★ 名家经典白名单（约 70 位教材级作者 + 55 篇名篇题名）：正确句/拼句目标/AI 手牌优先抽白名单子集（子集 ≥6 句才启用偏好，防池空），回应"诗词库优先经典"。
3. 干扰字改为常用字表优先（45 常用诗字），邻域兜底；不变量校验（拼错必 NOT_IN_CORPUS）保留。
4. AI 手牌装填改为名家优先（fam ≥ handSize 时整手名家）。

**回归**：8 测试 57 条全过（fallback 测试一度抓到 bake 内残留引用导致烘焙降级，

## 4.23 真机反馈「选对时晃动有点晕」：震动曲线重做（2026-11-19）

**现象**：真机每次接对盖章时整屏晃动，体感发晕。

**根因**（不是幅度问题，是波形问题）：旧实现
`translate((floor(shakeT*40)%2) ? 1.2 : -1.2, 0.6)` ——

1. **水平往复是晕动最敏感的刺激**：前庭系统对"左右来回"远比"上下起伏"敏感，眼球被迫
   整屏追着移动再复位，即典型的视觉-前庭冲突；
2. **25ms 硬切 = 20Hz 方波**：无缓动、无衰减，4–5 次瞬跳在同一强度，视觉读作"抖"而非"震"；
3. **垂直分量是固定 +0.6px 不振荡**：整屏在抖动期间一直偏下 0.6px，观感是"歪着抖"；
4. **作用范围覆盖全屏**（HUD/计时环/字块/按钮全在同一个 translate 里），没有着力点。

**修复**：`shakeOffset(t)` = 单周期正弦 × 线性衰减，返回**标量**（只有 y）：

| t | 0 | 32ms | 65ms | 80ms | 130ms |
|---|---|---|---|---|---|
| 位移 | 0 | **+1.20px**（落下） | 0（触底） | **-0.40px**（微回弹） | 0 |

- 一个来回就走完，之后恒 0 —— 观感是一声"咚"，不是抖动；
- 无横向分量（返回标量，结构上排除）；
- 时长 120→130ms、峰值 1.2px，`reduceMotion` 时完全不震。

**验证**：新增 `tests/shake.test.js` 8 条锁形状不变量——①标量/单参 ②全程 ≤1.3px ③符号
只翻转 1 次（两次以上即往复抖动）④首尾归零且下沉 > 2× 回弹 ⑤三段单调无折返 ⑥超时恒 0
⑦低帧率仍采到 ≥0.9px 冲击 ⑧源码级：震动 translate 的 x 分量必须为 0。全量 **13 文件 94 条**
全过、CI 15/15、冒烟三模式 ok、bundle 262.1KB。
